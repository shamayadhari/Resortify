# Deploying Resortify

Two pieces: the **API** (`backend/`, needs MongoDB) and the **web app** (repository root).

## 1. Before you deploy

1. Create a MongoDB Atlas cluster (or use the `mongo` service in `docker-compose.prod.yml`). Restrict network access to your API host.
2. Generate a strong secret: `node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"`.
3. Decide two public addresses, e.g. `https://resortify.example.com` (web) and `https://api.resortify.example.com` (API). Both must be HTTPS.
4. After the first deploy create an administrator: run `ADMIN_EMAIL=you@example.com ADMIN_PASSWORD='Str0ngPass1' npm run seed` inside `backend/` (or `docker compose exec api node src/seed.js` with those variables). It also adds a starter rewards catalogue.

## 2a. One machine with Docker Compose

```
cp .env.prod.example .env.prod      # fill in JWT_SECRET and the two URLs
docker compose -f docker-compose.prod.yml --env-file .env.prod up -d --build
```
Web listens on 127.0.0.1:3000, API on 127.0.0.1:5000. Put Caddy, nginx or a cloud load balancer in front for HTTPS and route the web domain to :3000 and the API domain to :5000. Photos persist in the `uploads` volume, the database in `mongo-data`. Back both up.

## 2b. Separate hosts

**API** (Render, Railway, Fly, a VM): build `backend/Dockerfile`, or run `npm ci --omit=dev && npm start` in `backend/`. Environment:

| Variable | Value |
|---|---|
| NODE_ENV | production |
| MONGODB_URI | your Atlas connection string |
| JWT_SECRET | the secret from step 1 (32+ characters; the API refuses to start with a weak one in production) |
| CLIENT_URL / CORS_ORIGINS | the web address |
| TRUST_PROXY | 1 when behind one proxy, so rate limits see real client IPs |
| UPLOAD_DIR | a persistent disk path (photos are stored on disk) |

**Web**: the project's default build targets Cloudflare Workers (`wrangler.jsonc` is generated by the build): set `VITE_API_BASE_URL` at build time and deploy with `npx wrangler deploy`. For a plain Node host use `Dockerfile.web`, or `NITRO_PRESET=node-server npx vite build` then `node .output/server/index.mjs`. `VITE_API_BASE_URL` is baked in at build time.

## 3. After deploying

- `GET <api>/api/health` returns `{ ok: true, db: "connected" }`. Use `/api/health/live` for container liveness checks.
- Sign in as the admin, then **Users & partners** to verify the first dealers, recyclers, collectors and NGOs, and **Facilities** to verify their places. Until then partners can sign in but cannot act.
- Uploaded photos are served from the API at `/uploads/...` with a 7-day cache.

## Security checklist (already in the code, verify in your environment)

- [ ] HTTPS everywhere; `TRUST_PROXY` matches your proxy count
- [ ] `JWT_SECRET` is unique and kept out of git (`.env` files are git-ignored; never commit `.env.prod`)
- [ ] MongoDB is not exposed to the internet
- [ ] CORS lists only your web origin
- [ ] Back up MongoDB and the uploads volume
- [ ] Run `npm audit --omit=dev` in `backend/` regularly (CI does)

## Tests

- API: `cd backend && npm test` (needs a MongoDB at `mongodb://127.0.0.1:27017`, or set `TEST_MONGODB_URI` to a database name ending in `_test`; each test file uses its own throw-away database).
- Web: `npx vitest run`, `npx tsc --noEmit` from the repository root.
